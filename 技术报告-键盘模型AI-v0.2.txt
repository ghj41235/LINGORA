一、架构总览
═══════════════════════════════════════════════════════════════

1.1 核心理念

键盘模型 AI 是一种非 Transformer、非神经网络、非 LLM 的类人记
忆型 AI 系统。不使用反向传播、不使用 GPU 矩阵运算、不使用向量
嵌入。核心机制：

  · 记忆 = 数百万个无标签"键"（Key），存储经历碎片
  · 思考 = 电流沿电线传导（Conduction），激活扩散
  · 学习 = Hebbian 规则：一起亮的键之间电线加粗
  · 遗忘 = 长期不同时亮的键之间电线缓慢变细
  · 语言 = 亮键格局的直接外溢——传导路径驱动句子构建

1.2 核心约束

  ┌────────────┬─────────────────────────────────┐
  │ 约束       │ 值                              │
  ├────────────┼─────────────────────────────────┤
  │ 不吃 GPU   │ 全部在 CPU 上运行                │
  │ 吃存储     │ 能力随键数量增长                  │
  │ 本地优先   │ 不联网，数据不外传                │
  │ 持续运行   │ 键亮度不归零（残留机制）           │
  │ 三段亮度   │ 0=关 / 1=中 / 2=大（三元非二元）  │
  └────────────┴─────────────────────────────────┘

  - 名称：代码中不出现这些词（注释中的否定声明除外）
  - 概念：不以任何其他名词实现上述数学结构
  - 代码：不引入上述计算模式，包括被其他名称包装的等效实现

  唯一的"学习"机制是本项目定义的：
  - 传导（Conduction）：推力沿电线扩散，逐跳衰减 ×0.65
  - Hebbian 增强：一起亮的键之间电线加粗
  - 电线衰减：不同时亮的键之间电线缓慢变细
  - NARS 证据量：频率 × 置信度 → 期望值
  - HTM 时序状态机：预测状态 0→1→2
  以上全部是符号化/图论/逻辑运算，不含任何微分、矩阵、概率采样。

1.3 为什么 CPU 就够

每跳传导推力衰减 ×0.65，5-6 跳后自然熄灭。一次完整"思考"仅需
3-6 轮迭代，每轮约 1ms（Python 原型，500 键）。GPU 的 kernel
启动延迟（~10μs）加上 CPU↔GPU 数据搬运时间，够 CPU 跑完整个
思考过程。GPU 对这个架构而言是"用卡车送一封信"。

扩展到 50 万键之前，CPU 完全够用。

二、数据结构
═══════════════════════════════════════════════════════════════

2.1 键（Key）— src/core/key.py

记忆网络的最小存储单元。存储一个"经历碎片"（中文原文）。

  ┌──────────────────┬──────────────────────────────────────┐
  │ 字段             │ 说明                                 │
  ├──────────────────┼──────────────────────────────────────┤
  │ id: int          │ 自增唯一标识                          │
  │ content: str     │ 经历碎片内容（中文文本，原样存储）     │
  │ brightness: int  │ 当前亮度 ∈ {0, 1, 2}                 │
  │ created_at       │ 创建时间戳                           │
  │ last_activated_at│ 最近一次点亮时间                      │
  │ activation_count │ 累计激活次数                         │
  │ peak_brightness  │ 历史最高亮度                         │
  │ is_dormant       │ 是否已休眠                           │
  │ source           │ "master" / "external" / "internal"   │
  │ residual_until   │ 残留保护截止时间戳（多轮记忆）        │
  └──────────────────┴──────────────────────────────────────┘

关键行为：
  · activate(brightness): 激活到指定亮度（cap 到 2）
  · decay(): 自然衰减一档。亮度=1 且残留期未过 → 不归零
  · 休眠：30 天未激活 → 内容压缩到 ≤18 字，可唤醒
  · source="internal" 的键永不休眠（用于系统键）

2.2 电线（Wire）— src/core/wire.py

键与键之间的有向关联边，带粗细权重。

  ┌──────────────────────┬──────────────────────────────────┐
  │ 字段                 │ 说明                             │
  ├──────────────────────┼──────────────────────────────────┤
  │ key_from / key_to    │ 源键 → 目的键                    │
  │ thickness: float     │ 电线粗细（初始依赖上下文）        │
  │ co_activation_count  │ 共激活次数（遗忘曲线用）          │
  │ last_strengthened_at │ 最近一次加粗时间                  │
  └──────────────────────┴──────────────────────────────────┘

2.3 键网络（KeyNetwork）— src/core/network.py

管理所有键和电线的容器。提供：
  · create_key() / get_key() / all_keys()
  · set_wire() / get_wire() / get_neighbors()
  · get_bright_keys() / get_top_k_keys()
  · 统计：key_count, wire_count, dormant_count, total_iterations

2.4 ConductionResult — 传导结果

  ┌──────────────────────┬──────────────────────────────────┐
  │ 字段                 │ 说明                             │
  ├──────────────────────┼──────────────────────────────────┤
  │ iterations           │ 总迭代轮数                        │
  │ elapsed_ms           │ 耗时（毫秒）                      │
  │ final_pattern        │ 最终亮度格局 {key_id: brightness} │
  │ is_stable            │ 是否收敛稳定                      │
  │ is_hesitating        │ 是否处于犹豫状态                  │
  │ top_keys             │ 最亮的键列表                      │
  │ amplitude_history    │ 每轮振幅历史                      │
  │ cycles               │ 完成的思考轮次（外层循环）        │
  │ cycle_patterns       │ 每轮结束时的格局                  │
  │ direction_changed    │ 是否发生方向切换                  │
  │ activation_paths     │ 传导路径（★ v0.2 新增）          │
  └──────────────────────┴──────────────────────────────────┘

activation_paths 结构：
  {dst_id: (src_id, src_content, dst_content, wire_thickness, push_amount)}
  记录每个被推亮键的"来源键 + 电线粗细 + 推力大小"。


═══════════════════════════════════════════════════════════════
三、传导引擎 — src/core/conduction.py
═══════════════════════════════════════════════════════════════

"思考"的物理过程。不搜索、不匹配、不预测——电流顺电线跑，跑到
跑不动为止。

3.1 双层循环结构（★ v0.2 新增外层循环）

  外层：思考轮次（cycles）
    1. 种子键设亮度
    2. 内层：扩散→衰减→振幅→稳定
    3. 稳定后：记录格局，与前一轮比较
    4. 未收敛：取最亮的 K 个键重播种 → 下一轮
    5. 收敛（CYCLE_CONVERGENCE < 0.03）或方向切换 → 返回

  内层：传导迭代（iterations）
    1. 选焦点（当前最亮的 K 个键）
    2. 扩散（焦点加权）
    3. 衰减
    4. 算振幅 → 判断稳定（STABILITY_THRESHOLD < 0.05）

3.2 扩散算法（spread_activation）

推力公式：
  push = source_brightness × wire_thickness × HOP_DECAY × attention_weight

注意力加权：
  · 焦点键（top K 最亮）：FOCUS_BOOST = 1.5
  · 非焦点键：NON_FOCUS_DAMPEN = 0.3
  → 焦点键的电流强 5 倍，噪音被大幅压制

累积推力：
  多个源键同时推同一个邻居时，推力累积。累积值 ≥ JUMP_PUSH(1.0)
  → 邻居亮度 +1（不超过 2）。

3.3 传导路径追踪（★ v0.2 新增）

扩散时记录每个被激活键的"最佳来源"——贡献推力最大的源键。
路径跨迭代累积，跨循环保留（第一轮路径优先）。

用途：语言模块读取路径，知道"为什么这个键亮了"，从而构建
因果句而非随机拼接。

3.4 重播种（_reseeding）

每轮传导结束后：
  1. 取最亮的 RE_SEED_TOP_K(8) 个键
  2. 清空所有亮度
  3. 将这些候选键重新激活，作为下一轮的种子

效果：思考不会在第一轮稳定后就停止——可以用第一轮的结论
（最亮的键）作为线索，深入挖掘相关记忆。

3.5 关键参数

  ┌──────────────────────┬───────┬──────────────────────────┐
  │ 参数                 │ 值    │ 说明                     │
  ├──────────────────────┼───────┼──────────────────────────┤
  │ HOP_DECAY            │ 0.65  │ 每跳推力衰减系数         │

四、消化与遗忘 — src/core/digestion.py
═══════════════════════════════════════════════════════════════

4.1 Hebbian 消化（digest_after_conduction）

传导结束后，所有亮度 > 0 的键两两之间电线加粗。
  delta = BASE_DELTA(0.1) + (brightness_a × brightness_b × 0.05)

  两个都亮度=2：delta = 0.3（最大）
  一个=1 一个=2：delta = 0.2
  两个都=1：     delta = 0.15

4.2 批量新键消化（digest_batch_new_keys）

投喂文档后：
  · 新键之间全互连（粗度 0.3）→ 同批经历形成"记忆簇"
  · 新键与上下文键弱连（粗度 0.05）→ 锚定到已有知识

4.3 电线衰减（decay_wires）

长期不同时亮 → 电线缓慢变细。
  遗忘曲线：衰减速率 = 基础衰减率 × 重复衰减因子
  重复衰减因子 = 1.0 / (1.0 + 0.5 × (共激活次数 - 1))

  激活 1 次：因子 1.0（全速衰减）
  激活 10 次：因子 0.18（极慢，近乎永久）

4.4 键休眠（check_dormancy）

30 天未激活 → 内容压缩到 ≤18 字，标记为休眠。可唤醒。
source="internal" 的系统键（如体感时间键）永不休眠。

五、犹豫检测 — src/core/hesitate.py
═══════════════════════════════════════════════════════════════

当传导振幅持续不降（在 10-20 秒窗口内持平或上升），判定为"犹豫"。
犹豫时语言模块输出"师父，我在想……"类表达，而非强行给出答案。

参数：
  · 犹豫窗口：10-20 秒
  · 振幅阈值：持平或上升 → 犹豫
  · 下降但缓慢 → 仍在思考

六、输入解析 — src/inout/input.py
═══════════════════════════════════════════════════════════════

6.1 分层分词（★ v0.2 原生符号支持）

正则分段 → 中文走 jieba，非中文走符号正则 → 合并去重。

  · 中文段：jieba.lcut() + 停用词过滤 + len≥2
  · 符号段：正则提取英文/数字/数学运算符
    英文：[A-Za-zΑ-ωА-я]+
    数字：\d+(?:\.\d+)?
    符号：[+\-*/×÷=<>()\[\]{}^%&|!~@#$\\:;,.?]+
  → 原生支持数学符号、英文单词、希腊字母、俄文字母

6.2 分层匹配

  第一层：精确匹配（token 在 key.content 中）→ brightness=2
  第二层：同义词匹配（token 的标准词或同义词在 key.content 中）
          → brightness=1
  第三层：关联匹配（60% 字符命中，不直接设亮度，靠传导自然激发）
  第四层：无匹配 → 短期记忆池（7 天 TTL，再次触发则升级为正式键）

6.3 师父特权

师父输入的所有种子键亮度 +1（上限 2）。

6.4 短期记忆池

匹配不到的词进入短期记忆池。7 天内再次出现（Jaccard 相似度 > 0.6
与已存片段）→ 升级为正式键 + 弱连线到当前种子。

6.5 同义词表

11 组同义词（开心/难过/师父/法术/害怕/厉害/喜欢/朋友/家/吃/睡）。
支持标准词→同义词双向查找。


═══════════════════════════════════════════════════════════════
七、语言模块 — src/inout/language.py
═══════════════════════════════════════════════════════════════

★ v0.2 重大升级：从随机模板填空 → 传导路径驱动句子构建。

7.1 核心思路（v0.2 路径驱动）

旧版：取亮键列表 → 随机选模板 → 拼接内容 → 输出
新版：取亮键列表 + 传导路径 → 识别根键 → 按因果链构建句子 → 输出

路径告诉语言模块"为什么这个键亮了"：
  · 直接匹配 → 根键（种子键）→ 主语
  · 被推亮 → 子键 → 来自根键的因果连接

7.2 路径→句子映射

  单子键："[根]就是[子]"
  多子键："[根]，就是[子1]，还会[子2]"
  孙键链："[子]就是[孙]"（因果链的第二步）

  电线粗细 → 连接副词：
    wire ≥ 0.8  → "就是"（很确定）
    wire ≥ 0.6  → "会"（比较确定）
    wire ≥ 0.4  → "好像会"（不太确定）
    wire ≥ 0.2  → "好像跟"（模糊联想）
    wire < 0.2  → "也许跟"（几乎不确定）

7.3 时间感知（★ v0.2 新增）

语言模块读取键的 created_at 时间戳，40% 概率附加时间描述：
  · 刚刚 / 刚才 / 今天 / 昨天 / 前天 / 前几天 / 前一阵 / 很久以前
  · 罗小黑风格短语："昨天才学会的"、"前几天想到的呢"

7.4 性格修饰

  · 35% 概率以"师父"开头
  · 25% 概率以语气词（喵/嗯/哦）开头
  · 内容含兴奋词时 40% 概率以"！"结尾

十、主循环与运行时 — src/runtime/main.py

10.1 对话流程

  1. 冷却残留亮度（根据距上次对话的时长逐步衰减）
  2. 点亮体感时间键（当前时段）
  3. 解析输入 → 种子键
  4. 判断复杂度 → 设置跳数限制
  5. 执行传导（思考）
  6. 犹豫检测
  7. 生成回复（路径驱动 + 时间感知 + 性格修饰）
  8. 消化（Hebbian 配对）
  9. 标记残留（本轮最亮键保持微弱激活 ~2 分钟）
  10. 自动保存检查点

10.2 残留亮度管理（★ v0.2 新增）

  · RESIDUAL_TTL = 120 秒：对话结束后亮度=2 的键保持残留保护
  · RESIDUAL_COOL_PERIOD = 30 秒：每过 30 秒衰减一档
  · 残留期内亮度=1 不归零 → 下一轮对话能"记得刚才在说什么"

10.3 体感时间激活（★ v0.2 新增）

  每次对话前点亮当前时段键，参与传导和消化。新记忆自然连线
  到当前时段键 → 同时间段的记忆被关联在一起。

10.4 指令系统

  /help    帮助
  /status  键/线/迭代/知识库统计
  /save    立即保存检查点
  /sleep   保存并退出
  /memory  最近亮过的键（含时间）
  /find    搜索关键词
  /ingest  扫描 data/ 投喂新文件
  /backup  备份记忆文件
  /keys    列出所有键（含亮度/邻居数）

10.5 后台维护

  · cleanup_short_term()：每次对话后清理过期短期记忆
  · background_maintenance()：每 3600 秒执行电线衰减 + 休眠检查
  · 知识库维护：合并重复、清理低质量

12.1 设计思路

不创建标签式的时间戳键（会污染网络）。用两个独立机制：

12.2 体感时间：4 个固定昼夜键

十三、投喂质量过滤（★ v0.2 新增）
═══════════════════════════════════════════════════════════════

13.1 噪音过滤器（_is_noise）

  过滤以下模式（不建键）：
  · 纯数字/日期/时间："2024年3月15日"
  · 重复单字符 >4 次："哈哈哈哈哈"
  · URL 或文件路径
  · 中文字符占比 < 30%（乱码/纯符号）

13.2 批次内去重（_dedup_within_batch）

  基于字符 bigram 的 Jaccard 相似度。相似度 > 0.85 → 去重。
  只与最近 5 条比较（O(n) 而非 O(n²)）。

13.3 已有但未加强的过滤

  · 不含 CJK 字符的片段 → 已在 split_into_fragments 中过滤
  · Jaccard 相似度 ≥ 0.8 的已有键 → 激活旧键，不建新（find_similar_key）
