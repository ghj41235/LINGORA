一、架构总览
═══════════════════════════════════════════════════════════════

1.1 核心理念

键盘模型 AI 是一种非 Transformer、非神经网络、非 LLM 的类人记
忆型 AI 系统。不使用反向传播、不使用 GPU 矩阵运算、不使用向量
嵌入。核心机制：

  · 记忆 = 数百万个无标签"键"（Key），存储经历碎片
  · 思考 = 电流沿电线传导（Conduction），激活扩散
  · 学习 = Hebbian 规则：一起亮的键之间电线加粗
  · 遗忘 = 长期不同时亮的键之间电线缓慢变细
  · 理解 = CD 拆解：句子拆成原语键 + 词键 + 关系线
  · 语言 = 语法键网络：亮键格局驱动句子构建

1.2 核心约束

  ┌────────────┬─────────────────────────────────┐
  │ 约束       │ 值                              │
  ├────────────┼─────────────────────────────────┤
  │ 不吃 GPU   │ 全部在 CPU 上运行                │
  │ 吃存储     │ 能力随键数量增长                  │
  │ 本地优先   │ 不联网，数据不外传                │
  │ 持续运行   │ 键亮度不归零（残留机制）           │
  │ 三段亮度   │ 0=关 / 1=中 / 2=大（三元非二元）  │
  └────────────┴─────────────────────────────────┘

1.2.1 设计边界（Design Boundaries）

  以下技术在本项目中 不使用——不仅是名称，包括其底层概念、
  数学结构、代码模式，无论以任何形式出现：

  ┌──────────────────────────────────────────────────────┐
  │ 不采用的技术（名称）        │ 对应的概念/代码形态            │
  ├──────────────────────────────────────────────────────┤
  │ LLM / 大语言模型            │ 自回归 token 生成             │
  │ GPT / Claude / LLaMA / 等   │ next-token prediction        │
  │ 小模型 / Small LM / SLM     │ 任何规模的参数化语言模型       │
  │ Transformer                 │ self-attention / QKV 注意力  │
  │ Neural Network / 神经网络   │ 层、神经元、激活函数           │
  │ CNN / RNN / LSTM / GRU      │ 卷积核、循环单元、门控         │
  │ Embedding / 向量嵌入        │ 稠密向量表示、余弦相似度        │
  │ word2vec / GloVe / BERT     │ 分布式语义向量                │
  │ Softmax / Sigmoid / ReLU    │ 任何激活函数作为计算单元        │
  │ Backpropagation / 反向传播  │ 链式法则求导、梯度下降          │
  │ Gradient Descent / 梯度下降 │ 损失函数、优化器、学习率         │
  │ Adam / SGD / 优化器         │ 参数更新规则                   │
  │ Matrix Multiplication       │ 大规模矩阵乘法作为核心运算       │
  │ GPU / CUDA / 并行矩阵       │ 硬件加速、批量矩阵运算           │
  │ PyTorch / TensorFlow / JAX  │ 任何深度学习框架               │
  │ Keras / HuggingFace / ONNX  │ 模型加载、模型格式              │
  │ Diffusion / Stable Diffusion│ 扩散模型、去噪过程              │
  │ GAN / 生成对抗网络          │ 生成器-判别器博弈               │
  │ Reinforcement Learning      │ 神经网络策略梯度               │
  │ Fine-tuning / Pre-training  │ 预训练+微调范式                │
  │ Tokenization (BPE/WordPiece)│ 子词分词器、vocabulary 词表     │
  │ .pt / .bin / .safetensors   │ 模型权重文件格式               │
  └──────────────────────────────────────────────────────┘

  这条边界覆盖"名称、概念、代码"三个维度：
  - 名称：代码中不出现这些词（注释中的否定声明除外）
  - 概念：不以任何其他名词实现上述数学结构
  - 代码：不引入上述计算模式，包括被其他名称包装的等效实现

  本项目定义的"学习"机制是：
  - 传导（Conduction）：推力沿电线扩散，逐跳衰减 ×0.65
  - Hebbian 增强：一起亮的键之间电线加粗
  - 电线衰减：不同时亮的键之间电线缓慢变细
  - NARS 证据量：频率 × 置信度 → 期望值
  - NARS 推理：演绎 / 归纳 / 类比（RULE 键，能量预算）
  - HTM 时序状态机：预测状态 0→1→2
  - CBR 案例：激活模式快照复用（低温快速路径）
  - Copycat 温度：全局温度调控搜索广度 + 概念滑移
  以上全部是符号化/图论/逻辑运算，不含任何微分、矩阵、概率采样。

1.3 为什么 CPU 就够

每跳传导推力衰减 ×0.65，5-6 跳后自然熄灭。一次完整"思考"仅需
3-6 轮迭代，每轮约 1ms（Python 原型，500 键）。GPU 的 kernel
启动延迟（~10μs）加上 CPU↔GPU 数据搬运时间，够 CPU 跑完整个
思考过程。GPU 对这个架构而言是"用卡车送一封信"。

扩展到 50 万键之前，CPU 完全够用。

二、数据结构（键 · 线 · 网络 · 花盆 · 花园）
═══════════════════════════════════════════════════════════════

2.1 键（Key）— src/core/key.py

记忆网络的最小存储单元。存储一个"经历碎片"（中文原文）。

  ┌──────────────────┬──────────────────────────────────────┐
  │ 字段             │ 说明                                 │
  ├──────────────────┼──────────────────────────────────────┤
  │ id: int          │ 自增唯一标识                          │
  │ content: str     │ 经历碎片内容（中文文本，原样存储）     │
  │ brightness: int  │ 当前亮度 ∈ {0, 1, 2}                 │
  │ primitive        │ 原语类型（WORD/IS/EAT/…，v1.0 新增）  │
  │ slots            │ 命名槽位（对其它键的 ID 引用）         │
  │ evidence_freq    │ NARS 正面证据占比（v1.0 新增）        │
  │ evidence_conf    │ NARS 证据置信度（v1.0 新增）          │
  │ prediction_state │ HTM 预测状态 0/1/2（v1.0 新增）       │
  │ created_at       │ 创建时间戳                           │
  │ last_activated_at│ 最近一次点亮时间                      │
  │ activation_count │ 累计激活次数                         │
  │ peak_brightness  │ 历史最高亮度                         │
  │ is_dormant       │ 是否已休眠                           │
  │ source           │ "master" / "external" / "internal"   │
  │ residual_until   │ 残留保护截止时间戳（多轮记忆）        │
  └──────────────────┴──────────────────────────────────────┘

关键行为：
  · activate(brightness): 激活到指定亮度（cap 到 2）
  · decay(): 自然衰减一档。亮度=1 且残留期未过 → 不归零
  · 休眠：30 天未激活 → 内容压缩到 ≤18 字，可唤醒
  · source="internal" 的键永不休眠（用于系统键）

2.2 电线（Wire）— src/core/wire.py

键与键之间的有向关联边，带粗细权重。v1.0 新增关系类型、滑移
距离、时序上下文三组字段：

  ┌──────────────────────┬──────────────────────────────────┐
  │ 字段                 │ 说明                             │
  ├──────────────────────┼──────────────────────────────────┤
  │ key_from / key_to    │ 源键 → 目的键                    │
  │ thickness: float     │ 电线粗细（Hebbian 加粗，衰减变细）│
  │ relation_type        │ 关系类型（v1.0 新增）            │
  │ context: dict        │ 时序上下文 {前置键ID: 共现次数}    │
  │ co_activation_count  │ 共激活次数（遗忘曲线用）          │
  │ last_strengthened_at │ 最近一次加粗时间                  │
  └──────────────────────┴──────────────────────────────────┘

关系类型（5 值）与极性（三态）：
  ┌─────────────┬────────┬──────────────────────────────┐
  │ relation_type│ 极性   │ 含义                         │
  ├─────────────┼────────┼──────────────────────────────┤
  │ same-as     │ +1     │ 完全等同（同原语键之间）       │
  │ similar-to  │ +1     │ 同类相似                      │
  │ part-of     │ +1     │ 部分-整体                     │
  │ cause-of    │ +1     │ 因果                          │
  │ opposite-of │ -1     │ 对立（抑制）                  │
  └─────────────┴────────┴──────────────────────────────┘

  极性是关系类型的固定属性（由 relation_type 查表派生），不是随机
  数、不是阈值。+1 激活、-1 抑制、0 无关联。

滑移距离（Copycat 概念滑移，v1.0 新增）：
  same-as=0, similar-to=1, part-of=1, cause-of=1, opposite-of=2

  滑移距离越小，两个概念越容易互相"借用"——高温时允许沿滑移
  距离小的关系线做类比联想，低温时禁止。

2.3 键网络（KeyNetwork）— src/core/network.py

管理所有键和电线的容器。提供：
  · create_key() / get_key() / all_keys()
  · set_wire() / get_wire() / get_neighbors()
  · get_bright_keys() / get_top_k_keys()
  · 统计：key_count, wire_count, dormant_count, total_iterations

2.4 花盆（Pot）— src/core/pot.py

花盆是键网络的软隔离容器。每个盆内有独立的 KeyNetwork 实例，
盆内传导规则与键盘模型完全一致。盆之间通过桥接线进行有限联想。

  · 生命周期：创建 → 生长 → 拆分 / 合并 / 休眠
  · 拆分：盆内键数超上限且出现低连通子群 → 拆出独立盆
  · 合并：两盆主题签名高度相似且长期无增长 → 合并
  · 休眠：盆长期无激活 → 整盆休眠（可唤醒）
  · 注意力权重：v1.0 增加，决定盆在传导中的参与度

2.5 花园（Garden）— src/core/garden.py

花园是盆栽的集合 + 跨盆桥接表，系统的顶层容器。在键盘模型
外面加了一层三维空间结构：

  · 管理盆的生命周期（创建 / 拆分 / 合并 / 休眠）
  · 管理桥接线（创建 / 触发 / 消化 / 衰减）
  · 跨盆传导（三轮流程：盆内传导 → 桥接评估 → 浅跳）
  · 投喂路由（按主题签名选择目标盆）
  · 维护 workspace（当前对话的工作空间）、grammar_library、
    case_library、inference energy budget

三、概念原语体系 — src/core/primitives.py
═══════════════════════════════════════════════════════════════

3.1 设计思路

罗小黑理解世界的原子意义单位。每个原语定义一种基本的概念结构，
所有投喂文本都被拆解为以原语为核心的概念键簇。

参考 Schank (1972) 概念依赖理论（Conceptual Dependency），但做了
大幅简化，去掉不必要的抽象层级。原语键本身存在于键网络中，拆解
过程由语言盆中的模式键驱动——不是独立的"消化模块"。

3.2 原语清单（35 个 = 29 概念原语 + 6 机制原语）

  ┌──────────┬────────────────────────────────────────────┐
  │ 类别     │ 原语                                       │
  ├──────────┼────────────────────────────────────────────┤
  │ 感知(5)  │ SEE 看 · HEAR 听 · SMELL 闻 · TASTE 尝     │
  │          │ · TOUCH 触                                 │
  │ 存在(4)  │ IS 是 · NOT 非 · HAVE 有 · NOT_HAVE 无     │
  │ 行动(7)  │ MOVE 移动 · GIVE 给 · EAT 吃 · SAY 说      │
  │          │ · MAKE 造 · USE 用 · CAN 能                │
  │ 关系(11) │ BIGGER 更大 · SMALLER 更小 · INSIDE 在内    │
  │          │ · OUTSIDE 在外 · BEFORE 先 · AFTER 后       │
  │          │ · CAUSE 导致 · LIKE 喜欢 · DISLIKE 厌恶     │
  │          │ · SAME 相同 · CONNECT 相连                 │
  │ 数量(2)  │ MANY 多 · FEW 少                           │
  ├──────────┼────────────────────────────────────────────┤
  │ 机制(6)  │ WORD 词键 · PATTERN 模式键 · RULE 规则键    │
  │          │ · CASE 案例键 · OUTPUT 输出键               │
  │          │ · SITUATION 情境键                         │
  └──────────┴────────────────────────────────────────────┘

3.3 槽位签名

每个原语有固定的槽位签名，槽位值是对其他概念键的 ID 引用：

  SEE(agent, target, result)   EAT(eater, food)
  IS(subject, category)        GIVE(giver, receiver, object)
  CAUSE(reason, effect)        LIKE(liker, liked)
  CAN(agent, action)           HAVE(owner, owned)

  数量原语（MANY/FEW）和情境原语（SITUATION）无槽位——它们是
  内在属性或标记键，不需要外部引用。

  槽位把"关系"从"内容字符串"中剥离出来：不是把"猫吃鱼"存成
  一个字符串，而是存成 EAT 原语键 + eater=词猫 + food=词鱼 +
  两条 part-of 线。这是 CD 拆解的核心。

四、CD 概念拆解 — src/inout/cd_engine.py
═══════════════════════════════════════════════════════════════

4.1 拆解流程

将输入文本拆解为概念键簇（原语 + 槽位）。消化发生在键创建时——
这是系统"理解"文本的入口：

  1. 文本 → 切句（句号/问号/感叹号/换行，短于 5 字的片段并入前句）
  2. 每句 → jieba 分词
  3. 分词 → 匹配 CD 模式（primitives.py 中的 CD_PATTERNS）
  4. 模式匹配 → 槽位填充（提取 X/Y/Z 等成分）
  5. 槽位填充 → 创建概念键簇（原语键 + 词键 + 连接线）

  示例："猫吃鱼"
    → 词键[猫] + 词键[鱼] + 原语键[EAT]
    → 线：词猫→EAT（part-of，eater 槽位）
    → 线：词鱼→EAT（part-of，food 槽位）

4.2 与旧版（v0.2）的区别

  v0.2：整句落成一个 WORD 键，内容字符串即全部信息——"猫吃鱼"
        只是一个字符串，系统不知道"吃"是关系、"猫"是主体。
  v1.0：句子被拆成原语键 + 词键 + 关系线——关系类型、极性、
        槽位都是可传导、可推理的结构，而非死字符串。

4.3 不依赖外部模型

不依赖任何 LLM、句法分析器、外部模型。拆解模式本身以 PATTERN
键的形式存储在语言盆中，可随使用强化或休眠。设计边界见
src/core/__init__.py。

五、花园模型与跨盆桥接 — src/core/garden.py
═══════════════════════════════════════════════════════════════

5.1 为什么要分盆

单一键网络在键数增长后会出现两个问题：
  · 传导串扰：不同主题的键互相推亮，噪音淹没信号
  · 无结构：所有键平铺在一个空间里，没有"领域"边界

花盆解决这两个问题：每个盆是独立子网络，盆内传导不跨域；盆与盆
之间只通过少量桥接线做有限联想。

5.2 盆的生命周期

  ┌──────────┬──────────────────────────────────────────┐
  │ 阶段     │ 触发条件                                 │
  ├──────────┼──────────────────────────────────────────┤
  │ 创建     │ 新文档主题签名与所有盆的余弦距离 > 0.7    │
  │ 生长     │ 投喂路由到最近的盆                       │
  │ 拆分     │ 盆内键数超 800，出现低连通子群            │
  │ 合并     │ 两盆签名高度相似 + 长期无增长 + 桥接够强  │
  │ 休眠     │ 盆 30 天无激活 → 整盆休眠（可唤醒）       │
  └──────────┴──────────────────────────────────────────┘

  主题签名：文档 → 64 维字符 bigram 频率向量 → 余弦相似度。

5.3 桥接线（Bridge Wire）

盆与盆之间的有限联想通道：

  · 创建：两盆内键的签名相似度 > 0.7 → 建桥接线
  · 初始粗度 0.25，每键最多 3 条桥
  · 触发：源盆键亮度=2 → 桥接评估 → 目标盆键亮度=1（浅跳）
  · 桥接最多 1 跳，防止跨盆无限扩散
  · Hebbian 加粗（+0.02），长期不用衰减（×0.001）

  桥接是"联想"不是"传导"——它只把另一个盆的键轻轻点亮，让
  目标盆有种子可以自己传导，而不是把电流灌过去。


═══════════════════════════════════════════════════════════════
六、传导引擎（三轮传导）— src/core/conduction.py
═══════════════════════════════════════════════════════════════

"思考"的物理过程。不搜索、不匹配、不预测——电流顺电线跑，跑到
跑不动为止。v1.0 从单网络传导升级为花园三轮传导。

6.1 三轮传导结构

  第一轮（盆内传导）：
    种子键设亮度 → 焦点加权扩散 → 衰减 → 振幅稳定

  第二轮（桥接评估）：
    第一轮最亮的键（亮度=2）→ 查桥接线 → 目标盆键浅跳点亮

  第三轮（浅跳）：
    被桥接点亮的键作为种子，在目标盆内做一轮浅传导

  效果：先在"当前话题盆"内深想，再顺着桥接线联想相邻盆，
  最后在相邻盆内浅尝辄止——不会跑偏到十万八千里。

6.2 扩散算法（spread_activation）

推力公式：
  push = source_brightness × wire_thickness × HOP_DECAY × attention_weight

注意力加权：
  · 焦点键（top K 最亮）：FOCUS_BOOST = 1.5
  · 非焦点键：NON_FOCUS_DAMPEN = 0.3
  → 焦点键的电流强 5 倍，噪音被大幅压制

累积推力：
  多个源键同时推同一个邻居时，推力累积。累积值 ≥ JUMP_PUSH(1.0)
  → 邻居亮度 +1（不超过 2）。

6.3 传导路径追踪

扩散时记录每个被激活键的"最佳来源"——贡献推力最大的源键。
路径跨迭代累积，跨轮保留（第一轮路径优先）。

用途：语言模块读取路径，知道"为什么这个键亮了"，从而构建
因果句而非随机拼接。

6.4 外层循环（重播种）

  1. 取最亮的 RE_SEED_TOP_K(8) 个键
  2. 清空所有亮度
  3. 将这些候选键重新激活，作为下一轮的种子

  效果：思考不会在第一轮稳定后就停止——用第一轮的结论（最亮
  的键）作为线索，深入挖掘相关记忆。

6.5 关键参数

  ┌──────────────────────┬───────┬──────────────────────────┐
  │ 参数                 │ 值    │ 说明                     │
  ├──────────────────────┼───────┼──────────────────────────┤
  │ HOP_DECAY            │ 0.65  │ 每跳推力衰减系数         │
  │ JUMP_PUSH            │ 1.0   │ 跳档阈值                 │
  │ STABILITY_THRESHOLD  │ 0.05  │ 内层稳定阈值（归一化振幅）│
  │ CYCLE_CONVERGENCE    │ 0.03  │ 跨轮收敛阈值             │
  │ DIRECTION_CHANGE     │ 0.30  │ 方向切换阈值             │
  │ MAX_CYCLES           │ 5     │ 最多重播种轮次           │
  │ RE_SEED_TOP_K        │ 8     │ 每轮结束后重播种的键数   │
  │ FOCUS_TOP_K          │ 5     │ 每轮焦点键数量           │

七、NARS：证据量与推理
═══════════════════════════════════════════════════════════════

7.1 证据量（evidence.py）— 真值理论

基于 NARS（Non-Axiomatic Reasoning System）的证据量真值理论：
每个键的真实性不由 content 字符串定义，而由它和其他键的全部连线
历史定义。

  truth = (frequency, confidence)
    frequency ∈ [0,1]：正面证据占比
    confidence ∈ [0,1]：总证据量 / (总证据量 + K)

  期望值 expectation = confidence × (frequency - 0.5) + 0.5
    → 高 confidence + 高 frequency = 强信念
    → 低 confidence = 不确定（无论 frequency 多少）

  这与"信念 = 带不确定度的概率"（师父的核心哲学）一一对应：
  键不只是"亮/不亮"，而是"我相信这个键 + 我有多确定"。

证据来源：
  · 种子键（师父提到的）→ 强正面证据（conf +0.15）
  · 亮度=2 的激活键 → 正面（+0.10）
  · 桥接触发的跨域键 → 跨域正面（+0.12）
  · 犹豫/方向切换的参与键 → 负面（-0.08 / -0.05）

7.2 推理（inference.py）— 三种推理规则

推理规则本身是 RULE 类型的键，存储在内部盆中。推理不是独立的
引擎——推理规则键在传导后由模式匹配触发，执行动作（创建新键
或修改已有键的 evidence）。

  1. 演绎 (Deduction)：A→B ∧ B→C ⇒ A→C（传递链）
  2. 归纳 (Induction)：同类实例 → 泛化概念
  3. 类比 (Analogy)：A:B :: C:? → C:D（完成配对）

资源约束：每次推理消耗能量（InferenceEnergyBudget），防止无限
创建键。能量随对话恢复。

  ┌──────────────────────────┬───────┐
  │ 参数                     │ 值    │
  ├──────────────────────────┼───────┤
  │ 能量上限                 │ 100.0 │
  │ 每次对话恢复             │ +5.0  │
  │ 演绎消耗                 │ 10.0  │
  │ 归纳消耗                 │ 15.0  │
  │ 类比消耗                 │ 20.0  │
  └──────────────────────────┴───────┘

八、Copycat：温度与概念滑移 — src/core/temperature.py
═══════════════════════════════════════════════════════════════

8.1 全局温度

全局温度反映系统对当前理解的信心，控制传导的搜索广度：

  ┌─────────────────────────────────────────────────────────┐
  │ 高温（> 0.7）│ 不确定，广撒网——跳数多、阈值低、滑移启用  │
  │ 中温（0.3-0.7）│ 有一定方向——定向搜索                     │
  │ 低温（< 0.3）│ 很确定——收敛到最佳答案，范围收窄          │
  └─────────────────────────────────────────────────────────┘

  温度范围 [0.05, 0.95]，基线 0.5（默认中温）。

温度调节（符号规则，非梯度）：
  · 种子稀缺 → 升温（+0.20 权重）
  · 种子跨盆分散 → 升温（+0.15）
  · 师父追问 → 降温（-0.15，聚焦）
  · 上轮犹豫 → 升温（+0.12，换思路）
  · 每次对话后 → 向基线回归（+0.05 速率）

8.2 概念滑移（Slippage）

滑移距离越小，两个概念越容易互相"借用"。温度决定哪些关系线
允许滑移：

  · 温度 ≥ 0.3 → 启用 similar-to / part-of / cause-of 滑移
  · 温度 ≥ 0.7 → 启用 opposite-of 滑移（对立概念类比）

参考 Hofstadter & Mitchell (1995) Copycat——不是做字母串类比，
而是借其"滑移"概念：高温时允许概念沿关系线滑动，低温时收紧。

8.3 工作空间（Workspace）

当前对话的临时结构。激活过的键在工作空间中留下痕迹，下轮对话
时预热这些键（降低激活阈值），话题转换时衰减。

  · 每轮衰减 ×0.85
  · 痕迹强度 > 0.3 → 预热（跳档阈值 -0.15）
  · 话题转换 → 快速衰减

九、HTM：时序记忆与预测 — src/core/temporal.py
═══════════════════════════════════════════════════════════════

基于 HTM (Hierarchical Temporal Memory) 的三个核心机制映射到键网络：

9.1 时序记忆

电线的 context 字典记录"前置键→后置键"的共现模式：
  "刚提到小鱼干 → 现在说'盒子' → 优先激活'装小鱼干的铁盒'"

  传导后从路径提取"前置键→后置键"序列对，递增

9.2 预测状态机

键的 prediction_state 三步状态机：
  · 休眠(0) → 预测中(1) → 确认(2)

  预测由电线 context 驱动：当前激活键 → 查询出边 context →
  预测后续键。预测命中 → 正面证据增强；过期未命中 → 负面证据
  惩罚。

9.3 注意力聚焦

  对话模式：外部种子，聚焦种子盆
  独处模式：自发传导（workspace 残留为种子），注意力锁防内耗

  · 独处检测：5 分钟无师父输入 → 独处模式
  · 注意力锁：高 evidence_conf 的预测中键 → 优先在它们附近活动
  · 独处传导最多 2 跳，温度额外 +0.15（联想更自由）

十、CBR：案例推理 — src/core/case.py
═══════════════════════════════════════════════════════════════

基于案例推理 (Case-Based Reasoning) 映射到键网络——节能模式。

10.1 案例 = 激活模式快照

  · trigger_pattern：触发这个案例的种子键 ID 序列
  · activation_snapshot：传导后亮起的键及其亮度
  · response_pattern：输出时使用的键 ID 序列

10.2 快速路径（跳过传导）

  当前种子键模式 → 匹配已有案例的 trigger_pattern
  → 匹配成功 + 温度低（< 0.45）→ 直接加载 activation_snapshot
  → 跳过传导！

  效果：常见问题（"你是谁""今天天气"）不重新传导，直接复用
  历史激活模式——省时省力，像"熟能生巧"的直觉反应。

10.3 案例生命周期

  · 每次正常传导后，新模式 → 自动创建案例快照
  · 案例被成功复用 → 频率+1，evidence 增强
  · 复用时适配失败 → 进入"待修正"状态
  · 长期不用 → 休眠

  一切皆键+线：案例是激活模式的记忆，不是独立的推理引擎。

十三、产生式系统（社交懂事层）— src/core/production.py

  一切皆键+线：情境键由输入特征触发，元规则键在传导中匹配条件
  并执行动作。

十四、指代消解与 .frag 结构化投喂
═══════════════════════════════════════════════════════════════

14.1 指代消解（seedplan.py）

把输入里的指代词 / 疑问词转成机制键种子，让"你是谁"这类问题
能被锁定到 SELF / MASTER / QUEST 键上，再由传导够到答案。

  · 指代映射：你/小黑/罗小黑 → SELF，师父/我 → MASTER
  · 疑问映射：谁 → WHO，什么 → WHAT，为什么 → WHY，怎么 → HOW
  · 自我内容规则：只匹配明确的自我介绍句式（"我是/我叫"）
    或名字身份（含"罗小黑"）——不放裸"小黑"前缀，否则
    "小黑吃饭"这类经历键也会连上 SELF 桥，问"你是谁"答偏。

  纯符号：不产生任何新知识，只让某些键亮、调某些线的导电率。
  删掉本文件任何一条规则，网络不少一根线。

14.2 .frag 结构化投喂（frag.py）

.frag 是师父手写的结构化知识三元组（`主体 关系 客体`），直接
入网，绕过 cd_engine 的自然语言拆解。解决"种子不够"：
cd_engine 的 17 种生活句式匹配不了世界知识句式（X能Y / X是Y的
一种 / X连接Y），整句落 freeform 变死 WORD 键。.frag 把这些
句式直接结构化投喂。

  格式（三列最简，空白分隔，# 注释）：
    @概念
    手机 能 打电话
    猫 是一种 动物
    猫 不是 植物

  一个三元组展开为（完整方案 A）：
    2 个词键（WORD）+ 1 个原语键（带命名槽位）+ 线（带
    relation_type + 极性）。

  极性三态 -1/0/+1 落在"主体↔客体"的词键间线上，由关系词决定
  relation_type：
    猫 是 动物   → 词猫↔词动物 = part-of（+1）
    猫 不是 植物 → 词猫↔词植物 = opposite-of（-1）
  原语键↔词键的线固定 part-of（+1）。

  纯符号：不调 LLM，不越设计边界。只把结构化的碎片建成键和线。

15.1 分层分词（input.py）

正则分段 → 中文走 jieba，非中文走符号正则 → 合并去重。

  · 中文段：jieba.lcut() + 停用词过滤 + len≥2
  · 符号段：正则提取英文/数字/数学运算符
    英文：[A-Za-zΑ-ωА-я]+
    数字：\d+(?:\.\d+)?
    符号：[+\-*/×÷=<>()\[\]{}^%&|!~@#$\\:;,.?]+
  → 原生支持数学符号、英文单词、希腊字母、俄文字母

15.2 分层匹配

  第一层：精确匹配（token 在 key.content 中）→ brightness=2
  第二层：同义词匹配 → brightness=1
  第三层：关联匹配（60% 字符命中，靠传导自然激发）
  第四层：无匹配 → 短期记忆池（7 天 TTL，再次触发升级为正式键）

15.3 师父特权

师父输入的所有种子键亮度 +1（上限 2）。

15.4 文档投喂（ingest.py）

  · 扫描 data/ 目录投喂新文件
  · 句子 → 碎片 → CD 拆解 → 概念键簇
  · 按主题签名路由到目标盆
  · 噪音过滤 + 批次内去重（见第二十一章）

十六、消化与遗忘 · 犹豫检测
═══════════════════════════════════════════════════════════════

16.1 Hebbian 消化（digestion.py）

传导结束后，所有亮度 > 0 的键两两之间电线加粗。
  delta = BASE_DELTA(0.1) + (brightness_a × brightness_b × 0.05)

  两个都亮度=2：delta = 0.3（最大）
  一个=1 一个=2：delta = 0.2
  两个都=1：     delta = 0.15

16.2 批量新键消化

投喂文档后：
  · 新键之间全互连（粗度 0.3）→ 同批经历形成"记忆簇"
  · 新键与上下文键弱连（粗度 0.05）→ 锚定到已有知识

16.3 电线衰减

长期不同时亮 → 电线缓慢变细（但永不断，MIN_THICKNESS=0.001）。
  遗忘曲线：衰减速率 = 基础衰减率 × 重复衰减因子
  重复衰减因子 = 1.0 / (1.0 + 0.5 × (共激活次数 - 1))

  激活 1 次：因子 1.0（全速衰减）
  激活 10 次：因子 0.18（极慢，近乎永久）

16.4 键休眠

30 天未激活 → 内容压缩到 ≤18 字，标记为休眠。可唤醒。
source="internal" 的系统键（如体感时间键）永不休眠。

16.5 犹豫检测（hesitate.py）

当传导振幅持续不降（在 10-20 秒窗口内持平或上升），判定为
"犹豫"。犹豫时语言模块输出"师父，我在想……"类表达，而非
强行给出答案。犹豫的参与键获得负面证据。

十七、语言输出 — src/inout/language.py
═══════════════════════════════════════════════════════════════

v1.0 语言输出由语法键网络驱动（见第十一章），路径生成作为降级
路径（语法键未命中时）。

17.1 路径驱动生成（降级路径）

取亮键列表 + 传导路径 → 识别根键 → 按因果链构建句子：

  单子键："[根]就是[子]"
  多子键："[根]，就是[子1]，还会[子2]"
  孙键链："[子]就是[孙]"（因果链的第二步）

  电线粗细 → 连接副词：
    wire ≥ 0.8  → "就是"（很确定）
    wire ≥ 0.6  → "会"（比较确定）
    wire ≥ 0.4  → "好像会"（不太确定）
    wire ≥ 0.2  → "好像跟"（模糊联想）
    wire < 0.2  → "也许跟"（几乎不确定）

17.2 时间感知

语言模块读取键的 created_at 时间戳，40% 概率附加时间描述：
  · 刚刚 / 刚才 / 今天 / 昨天 / 前天 / 前几天 / 前一阵 / 很久以前
  · 罗小黑风格短语："昨天才学会的"、"前几天想到的呢"

17.3 性格修饰

  · 35% 概率以"师父"开头
  · 25% 概率以语气词（喵/嗯/哦）开头
  · 内容含兴奋词时 40% 概率以"！"结尾
  · 随机语气词：喵、嗯、哦、啊、呀

二十、主循环与运行时 — src/runtime/main.py

20.1 对话流程（v1.0）

  1. 冷却残留亮度（根据距上次对话的时长逐步衰减）
  2. 点亮体感时间键（当前时段）
  3. 解析输入 → 种子键
  4. 指代消解（代词 → 机制键种子）
  5. A1 言外之力资格层（Frame 识别 + 门控检索 + 安全网）
  6. B 重构疑问词路由（relation_boost 探照灯）
  7. CBR 快速路径（匹配案例 + 低温 → 跳过传导）
  8. 花园三轮传导（盆内 → 桥接 → 浅跳）
  9. HTM 预测周期 + NARS 推理 + 犹豫检测
  10. 语法键网络生成回复（路径驱动降级 + 时间感知 + 性格修饰）
  11. 消化（Hebbian 配对）+ CBR 案例创建
  12. 标记残留（本轮最亮键保持微弱激活 ~2 分钟）
  13. 自动保存检查点

20.2 A1 门控检索（资格层）

  · 先识别输入在"问什么"（Frame），再决定哪些键有资格回答
  · 门控检索反查 subject=topic 的 IS 键，不靠传导亮度
  · 命中 → 确定性 frame 回答直接输出定义，不进传导（不受前轮
    残留污染）
  · 未命中 → 安全网"我还不太懂{topic}"

20.3 B 重构（疑问词路径驱动路由）

  撤销 same-as 偷换：旧版把所有关系线都当 same-as 处理，导致
  "猫吃鱼"的"吃"线和"猫是动物"的"是"线等价——读关系线时
  答非所问。B 重构：

  · 疑问词 → 目标关系类型（谁→part-of，为什么→cause-of，…）
  · 目标关系类型喂进 relation_boost 探照灯（×1.6 放大对应关系
    线的导电率）
  · 传导沿真实关系线走，读关系线不读最亮键

20.4 CBR 快速路径

  当前种子键模式匹配已有案例 + 温度低 → 加载案例快照作为强预热，
  减少传导跳数（见第十章）。

20.5 残留亮度管理

  · RESIDUAL_TTL = 120 秒：对话结束后亮度=2 的键保持残留保护
  · RESIDUAL_COOL_PERIOD = 30 秒：每过 30 秒衰减一档
  · 残留期内亮度=1 不归零 → 下一轮对话能"记得刚才在说什么"

20.6 体感时间激活

  每次对话前点亮当前时段键，参与传导和消化。新记忆自然连线到
  当前时段键 → 同时间段的记忆被关联在一起。

20.7 指令系统

  /help     帮助                /status   键/线/盆/桥/迭代统计
  /save     立即保存检查点      /sleep    保存并退出
  /memory   最近亮过的键        /find     搜索关键词
  /ingest   扫描 data/ 投喂     /backup   备份记忆文件
  /keys     列出所有键          /pots     列出所有花盆
  /bridges  列出桥接线          /cases    列出案例
  /remember 记忆一条            /kb       知识库查询/写入
  /write    在工作桌写草稿      /desk     看工作桌
  /clear    清理草稿            /split    手动拆分花盆
  /temp     查看/设置温度       /evidence 查看证据量

20.8 后台维护

  · cleanup_short_term()：每次对话后清理过期短期记忆
  · background_maintenance()：每 3600 秒电线衰减 + 休眠检查
  · 知识库维护：合并重复、清理低质量
  · 自动睡眠：长时间无输入自动保存退出

21.1 人格系统（src/personality/luoxiaohei.py）

LuoXiaoheiPersonality 数据类集中管理所有性格参数。

  身份：罗小黑，猫妖，叫用户"师父"
  语言风格：语气词（喵/嗯/哦/啊/呀），短句（≤40 字）
  称呼：40% 概率叫"师父"，兴奋时"师父师父！"
  脑回路：日常 1-2 跳，复杂问题 3-5 跳
  注意力：focus_top_k=5, focus_boost=1.5, non_focus_dampen=0.3
  师父信任：输入 +1 亮度，相关键衰减抵抗 0.5
  情感词：兴奋（厉害/好/棒）、困惑（不懂/难/奇怪）
  回应模板：启动/关闭/困惑/兴奋/犹豫各有预置表达

21.2 体感时间

不创建标签式的时间戳键（会污染网络）。用两个独立机制：

  · 体感时间：4 个固定昼夜键（早晨 05-10 / 下午 10-17 /
    傍晚 17-21 / 深夜 21-05），source="internal" 永不休眠，
    每次对话点亮当前时段键 → 同时段记忆自然关联
  · 描述时间：语言模块读键的 created_at 时间戳，算"刚刚/今天/
    昨天/…"，40% 概率融入回复

21.3 投喂质量过滤（ingest.py）

  · 噪音过滤器（_is_noise）：纯数字/日期、重复单字符 >4 次、
    URL/路径、中文字符占比 <30%（乱码）
  · 批次内去重（_dedup_within_batch）：字符 bigram Jaccard 相似度
    > 0.85 → 去重，只与最近 5 条比较（O(n) 而非 O(n²)）
  · 已有但未加强：Jaccard ≥ 0.8 的已有键 → 激活旧键，不建新
